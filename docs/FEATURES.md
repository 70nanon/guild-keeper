# Guild Keeper 機能バックログ

## 役割と使い方

本書は、ユーザーが選ぶゲーム機能、実装上の依存関係、進捗を管理します。ゲームデザインの正本は [GAME_DESIGN.md](GAME_DESIGN.md)、Phase 0〜6 の長期計画・検証指針は [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)、Codex の運用ルールは [AGENTS.md](../AGENTS.md) です。

フェーズや ID は厳密な着手順ではありません。依存関係には、ここで定義した機能を実装するために必要な機能だけを記載しています。依存が満たされれば、前のフェーズ全体を待たずに選べます。ユーザーが機能を選び、内部の技術作業は Codex が整理します。原則 1 機能を 1 PR とし、「大」の候補は選択時に範囲を再評価し、必要なら単独で価値を持つ機能に分割します。専用管理アプリや管理用スクリプトは導入しません。

本書の未実装機能は開発候補です。受け入れ条件は機能境界を示すもので、未決定の数値やルールを確定しません。各項目の判断事項は選択後・実装前に確認し、合意内容を仕様へ反映します。技術的に着手可能でも、判断が未了なら実装は開始しません。**ユーザーが明示的に選ぶまでは候補を実装しません。**

## 進捗と依存関係の判定

| 正式な状態 | 判定 |
| --- | --- |
| 未実装 | 最新の `main` に完了チェックと実装がなく、対象機能の進行中 PR もない |
| PR 進行中 | 対象機能の未マージ PR がある。実装ブランチでチェック済みでも正式完了ではない |
| マージ済み（実装完了） | 検証済みの実装と完了チェックが `main` に取り込まれている |

実装 PR では、検証後に対象機能のチェックを `[x]` に変更し、実装状態欄に検証記録・PR 番号を付記します。その PR が未マージの間は PR 進行中、`main` に取り込まれた時点で正式な完了記録になります。実装状態欄の過去の記述より、最新の `main` と PR の実際の状態を優先します。クローズされても未マージなら完了ではありません。チェックだけが入り実装を確認できない場合は不整合として調査します。

依存は **`main` の正式完了だけ** で判定します。未マージのチェックや別 PR の実装を依存解消に使いません。候補提示時は最新 `main` とコードを照合し、オープンな PR の ID・本文・差分を調べて重複提案を除外します。並行 PR 間の共有データ、保存形式、操作の競合も確認します。保存・購入解放など別機能が既に存在する場合の連携は選択した機能の PR で行いますが、それらを全機能の形式的な前提にはしません。仕様判断により実際の必須条件が変わる場合は、依存 ID と理由も更新します。
