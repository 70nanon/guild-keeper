# プレイテストのフィードバックと採用方針

## 位置づけ・確認した現状

2026-10-22 にユーザーから共有されたプレイテストの改善点と開発方針を記録します。独自に追加のプレイテストを行った記録ではありません。ゲーム仕様の正本は [GAME_DESIGN.md](GAME_DESIGN.md)、開発順序は [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)、機能 ID・依存関係・進捗は [FEATURES.md](FEATURES.md) を参照してください。

基準は最新 main `82b78b3`（PR #8 マージ済み）です。現行 MVP は注文の指定品・数量を満たし、手動の「勇者の帰還」で即時に返却・入荷し、任意の「翌日へ」で次の注文に進みます。配置・部分納品・受取待ち・支給／帰還記録をブラウザ内に自動保存します。自由な支給、支給前の取り戻し、自動出発、冒険タイマー、モード切替はまだありません。

**以下は採用した今後の方向性であり、この文書更新での実装・完了を意味しません。** F-000〜F-031 の ID と既存チェックは維持し、改善分を F-032〜F-036 の未実装項目として登録します。

### 自由支給で守ること

勇者のインベントリへの準備と支給の確定を区別します。確定前に戻せることを目的とし、アイテムを倉庫と勇者の両方で二重に使えないようにします。準備・取り戻し・確定・帰還・保存復元の各段階で個体の所有先を追跡し、消失・複製を防ぐことを実装時の検証条件にします。

現在の「必要数を満たすと注文完了」という判定を、そのまま自由支給の完了条件にはしません。「支給完了」をどう確定するかは未決定です。最後の品を置くだけで出発する、別の確認操作を置くなどの UI を、この文書では決めません。

### 冒険時間で守ること

出発時に確定した所要時間と、出発・帰還予定を復元できる時刻情報を保存します。画面のカウントダウン回数だけで経過を管理せず、再読込やブラウザを閉じた間の経過も反映します。閉じている間に帰還予定時刻を過ぎた場合も、再開時に完了を判定できる設計にします。閉じたブラウザ内で処理が動き続けることや、通知機能を前提にしません。

経過の判定と返却・戦利品の反映は同じ処理ではありません。冒険を識別する記録と処理済み状態を使い、タイマー更新・再読込・再開などが重なっても、同じ冒険の帰還・入荷は一度だけにします。所要時間をロード時に再抽選しません。端末時計の変更への対処や期限到達時の受け取り UI は未決定です。

冒険の1〜3分は、納品・整理を急がせる制限時間ではありません。冒険中の倉庫整理は継続でき、日が自動的に進む仕様にはしません。ストーリーモードへ同じ時間設定を適用するかは未決定です。

## 開発方針（採用）

**基本ループ MVP を整えた後、ストーリーモードより先にサンドボックス版を開発します。** 現行の継続プレイ MVP は土台として実装済みですが、今回の自由支給・出発・時間の変更は未実装です。基本ループの改善を検証し、サンドボックスで試せる機能を段階的に増やします。

| モード | 目的 | 機能の扱い |
| --- | --- | --- |
| サンドボックス | 倉庫番スキル・設備・鑑定・属性・レア度・自動化などの操作と組み合わせを自由に検証する | 実装済み機能を成長・報酬の進行に縛られず試せるようにする。未実装機能が使えるという意味ではない |
| ストーリー | 検証した倉庫作業を、勇者の成長と物語に組み込む | 共通の機能へ成長条件・解放順・報酬・物語を組み込む。条件の詳細や数値は未決定 |

在庫・配置・支給・冒険・帰還・入荷・機能そのもののゲームロジックは両モードで共通化し、機能を使える条件を分離します。サンドボックスの試用とストーリーの解放条件のために、同じ機能を別々に実装する方針にはしません。具体的な設定形式・切替 UI・セーブの分け方は未決定です。

Phase 0〜6 は引き続き長期の分類です。「サンドボックスを先に開発する」は全フェーズの機能を一括で実装する指示でも、次の実装機能を自動選択する指示でもありません。ユーザーが機能を選び、Codex が実際の依存と内部タスクを整理する運用を維持します。

## 未決定事項・実装前に判断すること

- 勇者のインベントリ容量、支給可能数、空の支給・不足品・持ちすぎの扱い、目的・行き先の生成内容。
- 支給の確定操作、確定前に倉庫へ戻す位置、戻す空きがない場合の扱い、準備中の保存と旧セーブからの移行。
- 自動出発後の取り消し可否、日送り可能な具体的状態。基本の循環は帰還を経て翌日とし、現行の遷移制約をどこまで引き継ぐかは実装時に判断する。
- 1〜3分の抽選分布・刻み、時間表示の単位、時刻情報の保存形式、時計を進めたり戻したりした場合の扱い。
- 期限到達時に即時入庫するか、帰還した勇者の受け取り操作を置くか。手動帰還ボタンの移行方法、自由支給後の返却・消耗・戦利品ルール。
- 入れ替え操作の文言・配置・案内方法。PC・スマホで未説明のプレイヤーが操作を見つけられるかを、人のプレイで再検証する。
- サンドボックスの試用設定、各スキル・鑑定・レア度の最小仕様と機能分割、モード切替と保存の扱い。ストーリーの解放条件・報酬・物語の具体化。
- 自由支給での目的別の探索補助・自動ピッキング・需要予測の意味づけ。F-011・F-020・F-022・F-031 を無断で別機能へ読み替えない。

## 今後の検証

自由支給で品を選ぶ判断が生まれるか、確定前に戻す操作が安心して使えるか、冒険中に整理したくなるか、1〜3分が待ち疲れにつながらないか、入れ替え導線が見つかるかを確認します。技術面では、支給前後と期限前後の保存復元、オフライン中の経過、帰還の再実行、容量不足と受取待ち、旧セーブの安全性を検証します。今回の報告を「各課題を解消済み」「人による全体の楽しさ評価が完了」とは扱いません。
