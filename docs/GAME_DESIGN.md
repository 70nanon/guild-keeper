# Guild Keeper ゲーム仕様書

## 位置づけと現状

本書はゲームデザインの正本です。フェーズと長期計画・完了条件は [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)、選択する機能・依存関係・進捗は [FEATURES.md](FEATURES.md) を参照してください。現在は Phase 0（開発基盤）が実装済みで、ゲーム機能は未実装です。本書に記載するゲーム体験は今後の開発方針であり、実装済み機能の一覧ではありません。

「確定」は現時点の方向性、「構想」は将来の候補、「未決定」は実装前に判断が必要な事項を示します。構想の記載は実装の許可や詳細仕様の確定を意味しません。

## ゲーム概要

- タイトル：Guild Keeper（仮）
- ジャンル：倉庫整理 × アイテムピッキング × 効率化 × 自動化
- 対象：PC・スマートフォンのブラウザ
- プレイヤーの役割：RPG 世界の勇者や冒険者の装備・消耗品を管理する倉庫番

最初にあるのは、大量のアイテムが雑然と放り込まれたひとつの巨大なインベントリです。毎朝届く注文に合う品を探して渡し、帰還した勇者が適当に戻した装備や戦利品を受け入れます。日々の仕事の中で、自分なりに倉庫を整理し、アップグレードを購入して作業を改善していきます。

将来は冒険者ギルド規模の倉庫へ発展し、分類・ピッキング・強化・合成・レイド用装備配分の自動化を目指します。これらを最初からすべて実装する必要はありません。

## コアとなる面白さ

**途方もない量の単純作業を、自分の工夫とアップグレードによって効率化していくこと。**

「こう整理すれば次から楽になる」「こんな機能があれば便利なのに」という発見を、配置の工夫や機能の解放につなげます。大量のアイテムが徐々に整然と並び、倉庫の景色が整っていく視覚的な快感も重視します。

整理は注文処理を助ける自発的な手段です。決められた正解の配置を強制したり、整理自体を毎日の義務にしたりしません。アップグレードでは数値だけでなく操作・作業方法そのものが変わることを目指します。自動化後も規模や条件の複雑さによって新しい改善の余地を生みます。

## 確定している基本方針

- ステージ制ではなく、ひとつの大きな倉庫を継続して管理する。ステージごとに初期化しない。
- 大量のアイテムがあること自体を体験の一部とする。
- 基本的に制限時間・ゲームオーバーを設けず、自分のペースで遊べる。
- 時間経過をリアルタイムで強制せず、プレイヤーが任意に日を進める設計を基本とする。
- 整理方法の自由度と、操作・作業方法を変えるアップグレードを重視する。
- PC とスマートフォンの両方で操作できる。

ギルド経営、勇者の直接操作、戦闘アクション、キャラクター育成を主目的としません。ステージごとに倉庫を初期化するパズルでもありません。ファンタジー世界は倉庫作業を楽しくする舞台設定であり、キャラクターやギルド施設よりインベントリを中心に据えます。

## 基本ゲームループ

| 順序 | 行動 | 体験・役割 |
| --- | --- | --- |
| 1. 朝 | 勇者から装備・消耗品の注文が届く | 今日探すものを把握する |
| 2. ピッキング | 大量の在庫から必要な品を探す | 配置や補助機能の有効性を感じる |
| 3. 納品 | 条件に合う品を渡す | 注文を処理する |
| 4. 整理 | 自由に並べ替え・分類する | 次の仕事に向けて改善する |
| 5. 帰還 | 装備や戦利品が雑然と戻る | 在庫と倉庫の状況が変わる |
| 6. 翌日 | 任意に日を進め、新しい注文を受ける | 改善効果を確かめる |

これは基本の流れであり、整理を行わなければ次へ進めない仕様ではありません。帰還と日送りの具体的な操作・発火タイミング、未完了注文がある日の進行は未決定です。

## 倉庫・アイテム・注文の概念

### 倉庫

長期にわたって同じ在庫・配置を管理する作業空間です。初期状態では巨大なインベントリがひとつ存在します。手動の並べ替えでプレイヤーが自分なりの分類を作れます。分類専用倉庫の増設は成長要素の構想です。容量、拡張上限、空きがない際の入荷処理、グリッド形式の詳細は未決定です。

### アイテム

装備、消耗品、戦利品を扱います。後半には強化・合成素材も想定します。名前・カテゴリによる探索が候補であり、性能・属性による条件の複雑化は後続フェーズで検討します。初期品目、個体と種類の識別、スタック、サイズ、所持数、消耗・返却の扱いは未決定です。

### 注文

冒険者がその日の冒険に必要な品を求める依頼です。在庫を選択し、注文に合う品を納品することが最小の遊びになります。最初は勇者ひとり、将来はパーティ・多数の冒険者へ拡張します。適合条件、数量、部分納品、誤納品、在庫不足、報酬、納品品の在庫からの除外方法は実装前の判断事項です。

## 成長段階（長期構想）

| 段階 | 仕事の変化 | 改善の候補 |
| --- | --- | --- |
| 序盤：勇者ひとり | 手動で大量の品から探し、自由に並べ替える | 対象品のハイライト |
| 中盤：パーティ | メンバー・注文・品種が増える | 分類専用倉庫、複数選択、一括移動、検索補助 |
| 後半：ギルド倉庫 | 大人数の依頼を扱う | 条件付き自動分類、注文対応の自動ピッキング、ルール設定 |
| 終盤：ギルド兵站 | 強化・合成素材の確保、レイド準備、共通装備の使い回し | 生産・配分の自動化、全体の最適化 |

段階の解放条件、移行タイミング、規模の数値は未決定です。自動化は倉庫作業の改善の延長として扱い、経営や戦闘の実装を前提にしません。

## アップグレード構想

以下は候補であり、採用・解放順・コスト・性能・バランスは未決定です。

| 改善対象 | 候補 |
| --- | --- |
| 探索 | 対象アイテムのハイライト、名前・カテゴリ検索、フィルター |
| 整理 | 分類専用倉庫、複数選択、一括移動 |
| 自動化 | 自動仕分け、条件指定による自動ピッキング、強化・合成の自動化 |
| 配分・計画 | 装備セット保存・一括配布、在庫管理、需要予測 |

検索やハイライトを最初からどこまで提供し、何をアップグレードで解放するかも判断が必要です。基本操作やアクセシビリティと、ゲーム内の効率化要素を混同しないよう検討します。

## UI・UX の設計方針

既存の深緑・金色を使った落ち着いたファンタジーデザインは活用可能です。現在のタイトル・準備中画面は開発基盤の表示であり、今後のゲーム画面のレイアウトを確定するものではありません。

- 画面の大部分をインベントリに割り当て、大量のアイテムを一覧できるようにする。
- 注文書をコンパクトに表示し、探索・選択・移動・納品を行いやすくする。
- スマホの縦画面でも快適に操作できるようにする。
- ドラッグだけに依存せず、タップでも操作を完結できるようにする。
- 視認性、選択状態の分かりやすさ、操作の気持ちよさを重視する。
- 整然と並ぶ倉庫の景色を楽しめるよう、一覧性と整理の結果を保つ。

具体的なレイアウト、セル寸法、注文の配置、移動・納品の操作手順、キーボード対応の詳細は今後検討します。

| 継続性 | セーブ形式・保存先・保存タイミング、互換性、復旧、端末間の扱い |

## 決定状況のまとめ

確定しているのは、倉庫作業とその改善を中心とするコンセプト、継続するひとつの倉庫、基本の日次ループ、自分のペース、整理の自由度、PC・スマホ対応という方向性です。

成長段階・アップグレード・自動化・生産・ギルド物流は長期構想です。数値、ルールの詳細、具体的な操作や技術方式は未決定です。実装タスクでは対象フェーズに必要な判断だけを明示して合意し、本書と実装計画を更新してください。
