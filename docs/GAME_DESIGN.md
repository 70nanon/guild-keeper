## 作品コンセプト（確定）

**「勇者にはならない。勇者を倉庫から支える。」**

才能はあるのに整理整頓が壊滅的に苦手な勇者が、既存のギルドの紹介で倉庫番を雇います。プレイヤーは装備の支給、持ち帰られた戦利品の整理、倉庫の効率化を担当します。冒険・戦闘を直接操作せず、裏方の日常業務から物語に関わります。

**主題：「ただ倉庫を整理していたら、いつの間にか世界を救う手助けをしていた」**

- 開発上のプロジェクト名と現在の表示タイトル：**Guild Keeper**。今回は変更しません。
- 作品の仮称：勇者の倉庫番。正式なタイトル変更は別タスクでまとめて行います。
- ジャンル：倉庫整理 × アイテムピッキング × 効率化 × 自動化。
- 対象：PC・スマートフォンのブラウザ。

物語が大きくなっても、主役は倉庫に並ぶ大量のアイテムと、その作業改善です。勇者の直接操作、戦闘アクション、キャラクター育成、ギルド経営全般を主目的にしません。ファンタジー世界は、倉庫を管理する日常を楽しくする舞台です。

## コアとなる面白さ・基本方針（確定）

**途方もない量の単純作業を、プレイヤー自身の工夫、倉庫番スキル、設備によって効率化すること。**

「こう整理すれば次から楽になる」「こんな機能があれば便利なのに」という発見を、自分の配置や能力・設備の成長につなげます。雑然とした大量の品が徐々に整い、倉庫の景色が変わる視覚的な快感も重視します。

- ひとつの倉庫を継続して管理し、ステージごとの初期化を基本ループにしません。
- 大量の品があること自体を体験に含めます。整理方法にひとつの正解を押しつけず、整理を毎日の義務にしません。
- 原則として制限時間・ゲームオーバーを設けず、自分のペースで作業し、任意に日を進める方針を維持します。冒険の全滅・復帰に関する例外案は未決定です。
- 成長で操作・作業方法と、アイテムから読み取れる情報が変わります。現行 MVP の機能を遡って封鎖する指示ではありません。
- 人員・物量が増える頃には、それを扱う効率化手段も増えるようにします。自動化後も分類ルール・需要・在庫配分などの判断を残します。
- PC・スマホで、ドラッグ必須にせず操作できるようにします。

## 自由支給・時間経過する冒険（現在の試遊版）

ユーザーの明示的な一括実装許可により、F-032・F-033・F-034 と操作改善をまとめて実装します。指定品・数量を満たす注文から自由支給へ置き換えます。初期160枠・48個・8品目各6個、元の個体 ID、F-008 の返却・入荷・受取待ち、F-009 の任意の日送り、F-010 の保存・破損保護を維持します。以下は基本ループを検証するサンドボックス向けの暫定ルールです。モード切替・成長要素の試用環境 F-036 を完成扱いにはしません。

### 予定確認 → 準備 → 出発 → 帰還 → 翌日

- **冒険予定**：街道の見回り・森での採集・山道の探索の短文を日ごとに循環表示する。指定品・必要数・装備による成否判定はない。
- **勇者の持ち物**：8枠・1枠1個。倉庫から好きな種類・個体を準備でき、出発前は倉庫へ戻せる。空の準備でも出発可能にし、在庫不足で詰まらないようにする。倉庫と勇者の両方に同じ個体を置かない。
- **準備完了**：「準備完了・出発」の確定で1日1回だけ自動出発する。出発後の支給・取り戻し・勇者の枠交換・出発取り消しはできない。倉庫の整理は準備中・冒険中・帰還後の全てで可能。
- **冒険時間**：出発時に60〜180秒を1秒刻みで一度だけ抽選する。開始時刻・所要時間・帰還予定時刻を保存し、今回の所要時間と残り時間を表示する。絶対時刻の差から計算するため、再読込や閉じていた間も経過を反映し、ロードで再抽選しない。画面を開いている間も残り時間を更新する。
- **帰還**：予定時刻に「帰還可能」へ移行し、「帰還を迎える」で1回だけ F-008 の返却・入荷を行う。武器・防具は同じ個体を全返却、消耗品は全消費、戦利品は既存8品目から2〜4個。冒険結果の良し悪しは判定しない。占有枠は動かさず、古い受取待ち→返却装備→戦利品の順で空き枠へランダム入庫し、入りきらない個体は保持する。
- **翌日**：帰還を迎えた後だけ「翌日へ」で進む。整理・受取待ちの解消は必須ではない。日付は自動で進まず、配置・在庫・受取待ち・冒険記録を維持する。日数上限は設けない。
- **時刻の前提**：端末の時計を使う。時計を進めると帰還可能になり、戻すと待ち時間が延び得る。サーバー時刻・改ざん防止・オフライン通知は導入しない。作業の時間制限やゲームオーバーとは区別する。

### ドラッグとタップの共通操作

PC はブラウザ標準のドラッグ、スマホは450msの長押し後にドラッグできる。空き枠へは移動、品のある枠へは交換。倉庫内・勇者内・倉庫と勇者の間で同じ移動判定を使い、勇者の枠に関係する変更は出発前だけ許可する。勇者や倉庫が満杯でも、占有枠を指定した交換で取り戻せる。

スマホは長押し前に8pxを超えて動けばドラッグ候補を解除し、通常の縦スクロールを妨げない。成立時は品を浮かせ、指に追従するプレビューと有効な移動先・現在のドロップ先を示す。端で300ms静止すると、そのスクロール領域を自動スクロールする。無効な場所、タッチキャンセル、複数指、画面非表示、Escapeでは移動を確定しない。ドラッグ中の見た目だけでは在庫を変更しない。

タップは品の確認・選択だけを行う。「移動・交換」→目的の枠で正確な場所へ移す。「勇者へ渡す」「倉庫へ戻す」は最初の空き枠へ移す補助で、空きがなければ無効にし、枠指定の交換は残す。移動先に元の枠を指定するか「選択を解除」で取り消せる。選択欄に操作名と進み方を常に示す。F-035 の実装・自動操作は検証するが、未説明の人による発見性の再評価は別に残す。

### 初期倉庫の暫定バランス

倉庫容量は160枠、新規開始・初期化時の品は既存8品目各6個、合計48個とする。種類を再現可能に混在させ、160枠全体へ約3〜4枠おきに分散配置する。空き112枠を残し、整理・支給・帰還・入荷を試しやすくする。無制限化・購入による倉庫拡張は実装しない。旧セーブには新しい初期配置・品数を適用せず、元の在庫を全て維持する。

### 保存 version 3 と version 1・2 の移行

- キー `guild-keeper.save` を維持し、`{ version: 3, state: ... }` に自動保存する。初期在庫数の基点（新規48個／旧データ96個）を記録し、それぞれの台帳と現物を照合する。倉庫・勇者の枠、準備中の品、日数、冒険ごとの支給個体・開始時刻・所要時間・帰還予定時刻・帰還結果、受取待ちを保持する。選択・移動モード・ドラッグ表示は復元しない。時間表示の更新だけではセーブを書き換えない。
- 初期在庫または検証済みの旧記録を基点に支給・帰還の台帳を照合し、現物の消失・重複、出発中の持ち物変更、時刻の不整合を拒否する。操作は冒険 ID と移動元の個体 ID を照合し、古い移動・二重出発・二重帰還・二重日送りを無効にする。
- version 2 は従来の96枠・96個の基点で整合性を検証し、先頭96枠の配置を動かさず末尾に空き64枠を追加する。日数・勇者の持ち物・冒険時刻・帰還結果・旧台帳・受取待ちの順序を維持し、移行時に再抽選・再入庫は行わない。保存は次回からversion 3となる。新規48個への減数や補充はしない。
- version 1 は従来の検証を通した後、元の JSON を `guild-keeper.save.v1-backup` に保存してから移行する。バックアップに失敗したら元データを上書きせず停止する。先頭96枠の配置・受取待ち・日数・旧注文／支給／帰還の全記録を保持し、末尾に空き64枠を追加する。
- 旧当日が未帰還なら、その日の支給個体を出発前の準備欄へ移す。既に支給した分を失わず、内容を確認して「準備完了」で新しい冒険へ進める。旧方式で9個支給していた場合は8個を準備欄、超過1個は受取待ちの末尾へ保持する。
- 旧当日が帰還済みなら帰還済みのまま再開し、再入荷せず「翌日へ」を選べる。旧記録は移行時の基点として保持し、新しい台帳の現物と二重計上しない。
- 未保存時の開始、破損・非対応・読込失敗時の上書き停止、書込失敗時の警告と前回保存の維持、確認付き初期化を継続する。保存は単一ブラウザの1枠。端末間同期・複数タブの同時編集・履歴圧縮は対象外。初期化後も移行元のバックアップは残す。

### サンドボックスを先に作る（採用方針・モード自体は未実装）

基本ループ MVP を整えた後、ストーリーモードより先にサンドボックス版を開発します。スキル・設備・鑑定・属性・レア度・自動化などを、成長条件に縛られず自由に試せる場を目指します。未実装機能をすべて先に作る条件にはせず、個別に選択・実装した機能から検証できるようにします（F-036）。

既存の注文向け補助・複雑条件・自動ピッキング等（F-011・F-020・F-022・F-031）は履歴と ID を保持します。自由支給との整合を取る際の意味・受け入れ条件は、各機能を選択して実装する前に見直します。方向性の採用だけで候補を実装しません。

## v0.1 MVP の記録（初回の暫定仕様）

以下は初回の実装記録です。**現在の進行・保存は後述の F-009・F-010 節が置き換えます。** 基本操作の検証のため、ユーザーの明示的な依頼により F-001・F-002・F-003・F-005・F-006・F-007 をひとつの PR で実装します。将来の経済・成長・日次ループの詳細を確定するものではありません。

- 初期倉庫は96枠・96個。8品目（剣、盾、回復薬、杖、薬草、兜、魔力の雫、靴）を各12個配置する。1枠1個でスタックせず、個体に一意の ID を持たせる。配置は再現可能な混在配置とし、リセット時も同じ状態に戻す。
- 勇者はひとり。固定の注文3件を順番に表示する。注文1は剣1・盾1・回復薬2、注文2は杖1・魔力の雫2・薬草1、注文3は兜1・靴1・回復薬1・薬草2。初期在庫で全件を達成可能にする。
- 品をタップ・クリックして選択。同じ品を再度選ぶと解除する。「納品する」で注文の未充足品を1個ずつ渡し、個体を在庫から取り除く。位置は詰めず空き枠を残す。不適合品・必要数を超える品は消費せず、理由を表示する。
- 「入れ替える」後に移動先をタップして品同士の交換か空き枠への移動を行う。元の枠を押すと移動モードを取り消し、解除ボタンで選択自体も取り消す。移動先を選ぶ間は納品しない。
- 数量を満たした時点で完了を表示する。「次の注文へ」で次の固定注文を表示し、在庫と配置は保つ。最終注文完了後は「最初から遊ぶ」で在庫・配置・注文進捗・選択をリセットする。
- **固定注文の連続表示とリプレイは MVP 用の暫定挙動であり、日送り・帰還を含む正式な日次サイクル（F-009）ではない。** 通常プレイ中に倉庫を初期化するステージ制にはしない。リプレイ時の初期化だけを明示的に行う。
- 同一ページで注文、倉庫、操作欄を扱う。ドラッグ不要のボタン操作とし、選択状態を色とチェックで示す。納品候補のハイライト（F-011）や本格的なアイコン制作（F-004）は行わず、品名・種類と基本8品目の独自 SVG アイコン試作を使用する。
- 初回 MVP では帰還・入荷・日送り・保存も対象外で、再読み込みは初期状態へ戻った。その後 F-008 の帰還、今回 F-009・F-010 の継続・保存へ発展する。アップグレード、自動化、複数倉庫・冒険者、性能・レアリティ、バックエンドは引き続き対象外。

将来の序盤で操作や情報を制限する構想は、この MVP へ適用しません。並び替えと詳細な品名は基本操作の検証のため維持します。本節以外の初期件数・スタック・日次ルール等の未決定事項は、長期仕様についての判断事項として残します。MVP の数値・品目は将来のバランスを確定しません。

## F-008：初回の手動帰還・ランダム入荷の記録

以下は旧MVPの記録です。現在の帰還契機・保存は前述の自由支給節に従います。初回は F-009 とは独立した検証用操作として実装しました。返却・抽選・容量超過の基本ルールは継続し、進行・保存だけを次節の継続プレイ仕様へ更新します。初期96枠・8品目は維持します。

- **契機**：注文完了後に「勇者の帰還」を押す。注文1件につき帰還は1回。未完了の依頼は処理せず、ボタンの依頼 ID と処理済み記録を検証して連打・古い操作による重複を防ぐ。
- **返却**：支給した武器・防具（剣・盾・杖・兜・靴）は100%返却し、元の個体 ID を維持する。回復薬・薬草・魔力の雫は全て使用済みとして返却しない。破損・返却率の抽選は導入しない。
- **戦利品**：2〜4個を同じ確率で抽選する。各品は既存8品目から等確率で独立抽選し、同品目の複数入荷を許す。帰還の依頼 ID と通し番号から専用の個体 ID を作り、初期品・別依頼の戦利品と区別する。新しい品目・性能・属性・レア度は追加しない。
- **配置**：既存の空き枠だけを無作為に選ぶ。占有中の枠は変更せず、プレイヤーの入れ替え・配置を維持する。現在選択中の品と移動モードは帰還処理後に解除する。
- **容量不足**：枠数を増やしたり在庫を上書きせず、入りきらない品の個体を「受取待ち」へ保持する。古い受取待ち、今回の返却装備、今回の戦利品の順に、入る分だけ空き枠へ配置する。受取待ちは追加倉庫ではなく入庫待ちの安全バッファで、直接選択・納品はできない。
- **再入庫**：「受取待ちを入庫」で、その時点の空き枠に再配置する。空きがなければ何も消費せず保持。部分的に入る場合は残りを保持し、再試行しても品目・数量・個体を再生成しない。並べ替えだけでは空き数は増えず、納品で空きを作れる。空きがなければ翌日以降も残りを受取待ちとして保持する。廃棄や容量拡張の機能は追加しない。
- **コメント**：帰還時に3種類の短文からひとつを表示する。返却・消耗・戦利品の個数も表示するが、冒険の成否・スコア・装備の性能による結果分岐は実装しない。コメントは最新1件を残す。
- **進行**：継続プレイでは当日の完了注文のみ帰還でき、帰還後に翌日へ進む。初回の「帰還を飛ばして固定注文へ進む」暫定操作は廃止する。
- **乱数と重複防止**：UI が操作時に乱数シードを渡し、ロジックは同じ状態・シードから同じ結果を得る。React の再評価で抽選が変わらない。処理済み依頼は再帰還せず、受取待ちを入庫しても抽選し直さない。
- **再読み込み・初期化**：帰還済み記録・実際の入荷個体・受取待ちも次節の自動保存対象にする。再読み込みで抽選や帰還を再実行しない。確認付きの「記録を初期化」だけが意図的な全初期化となる。

返却率、消耗率、戦利品のテーブル・量、コメント、受取待ちは MVP の暫定ルールです。長期の冒険・報告書の完成を意味しません。

## F-009・F-010：旧継続プレイ MVP の記録（version 1）

以下は PR #8 の実装記録で、現在の進行と保存は前述の自由支給・version 2 節に置き換えています。ユーザーが2機能の一括実装と簡潔な MVP ルールの採用を明示的に許可した範囲です。旧固定3注文・最終リプレイを継続プレイへ置き換えます。スキル・設備・成否判定・物語イベント・自動化は含めません。

### 日次サイクル（F-009）

- **1日1注文**：1日目は既存の「旅立ちの支度」（剣1・盾1・回復薬2）。初期在庫・96枠・8品目とタップによる納品・整理は維持する。
- **進め方**：注文を完了 → 「勇者の帰還」で一度だけ返却・入荷 → 自由整理 → 「翌日へ」。未完了・未帰還では日を進めない。整理はいつでも可能で、整理の実行・受取待ちの解消は日送りの条件ではない。制限時間や自動進行はない。
- **翌日の注文生成**：現在の倉庫セルにある種類から最大3種類を選び、各1〜3個、かつ実在する数量以下を要求する。種類を無作為に並べ、装備があれば1種類は装備を優先する。他の種類も最大2種類選ぶ。装備がなくても消耗品だけで生成できる。受取待ちは直接納品できないため生成の在庫数へ含めない。欠品で詰まらないための MVP 補助であり、長期の需要・難易度を確定しない。
- **継続性**：帰還では最低2個の戦利品が入るため、通常のサイクルで在庫が空のままにならない。セルが全て空の状態では受取待ちを入庫するよう案内し、空の注文は作らない。上限日数・最終注文・自動リプレイは設けない。
- **引き継ぎ**：日数・倉庫の全セルと個体・受取待ちの順序・日ごとの注文と支給個体・帰還記録と入荷個体を維持する。日送り自体は在庫や配置を変更しない。当日の充足数と選択だけを新しい注文向けに初期化する。
- **一意性**：注文 ID は `day-N`、戦利品 ID は `loot-day-N-連番`。操作は元の注文 ID・個体 ID を照合する。日送り・帰還の連打や前日の操作は無効となる。支給履歴に同じ返却装備が複数日現れることは正常だが、現物は倉庫・受取待ち・未帰還の支給先のいずれか1か所だけに存在する。

### 保存と復元（F-010）

- **保存先と形式**：このブラウザ・オリジンの `localStorage`、キー `guild-keeper.save`、JSON の `{ version: 1, state: ... }`。新規開始と状態変更後に同期 API で自動保存する。保存済み／失敗を注文帳へ表示する。新たなサーバー・依存ライブラリは使わない。
- **対象**：日数、生成済みの注文と部分納品、全セルの配置・個体、累計納品数、受取待ち、日ごとの支給履歴、帰還済み ID、返却・戦利品の実データとコメントを保存する。抽選結果を保存するためロードで再抽選しない。選択・移動モードと一時的な操作メッセージは再開時に解除する。
- **検証**：形式・バージョン、96セル、品目・数量・日付と注文 ID、完了・帰還の順序、納品数と支給記録、帰還数と返却個体・戦利品 ID を検査する。初期在庫から支給・帰還の台帳をたどり、残るべき個体と現物を照合し、消失・重複・不整合を拒否する。
- **未保存**：キーがなければ1日目から開始する。これまでの MVP に永続セーブは存在しないため、旧形式の移行は不要。将来の形式変更時は移行または互換性対応をその PR で判断する。
- **破損・非対応バージョン・読込失敗**：復元と自動保存を停止し、元の値を保持した警告画面を表示する。勝手に初期状態で上書きしない。設定修正・対応版での再読み込みを可能にし、記録の破棄は「記録を初期化して始める」の確認後だけ行う。
- **書込失敗**：容量不足・保存禁止などを捕捉し、直前の保存を維持する。メモリ上で操作は続けられるが未保存であることを明示し、次の状態変更で再試行する。確認付き初期化の保存も失敗すれば、再読み込みで以前の記録に戻る。
- **意図的な初期化**：「記録を初期化」は確認ダイアログ後に在庫・配置・日数・注文・全台帳・受取待ちを1日目へ戻して保存する。キャンセルでは何も変更しない。
- **制限・未決定**：保存は単一ブラウザ内の1枠。ブラウザのデータ削除・プライベートモード終了による消去、端末間同期、複数タブの同時編集は保証しない。履歴は削らず保持し、長期プレイでの容量制約は書込失敗として扱う。履歴圧縮・複数セーブ・エクスポート・同期・将来の移行方式は未決定かつ今回対象外。

## 基本ゲームループ（長期方針）

1. 朝：勇者が冒険の目的や行き先を伝える。序盤の勇者ひとりでは1日1依頼とする。
2. ピッキング・支給：倉庫番が必要と考える品を選び、勇者のインベントリへ準備する。確定前は倉庫へ戻せる。支給完了後に自動出発する。
3. 冒険：勇者たちが自律的に活動する。倉庫番は倉庫の整理を続けられる。戦闘は直接操作しない。サンドボックスでの所要時間は前述の1〜3分とする。
4. 帰還：短い冒険報告書と持ち帰った装備・戦利品を受け取る。
5. 整理・改善：品を並べ替え・分類し、業務達成と報酬でスキル・設備を充実させる。
6. 翌日：プレイヤーの操作で日を進め、新たな依頼を受ける。

このうち自由支給・冒険時間・帰還・日送りは前述の試遊版に実装します。報告書・成長・物語は長期構想です。整理は準備中・冒険中・帰還後に自由に行え、日送りの義務や整理の達成判定は設けません。現在の支給確定・帰還・日送り条件は前述の試遊版のルールに従います。報告書・成長はさらに後の構想です。

支援で勇者が前進 → 業務規模・戦利品が増える → 倉庫管理が上達・自動化 → さらに大きな冒険を支える、という循環を目指します。現在の MVP はこのうち注文・支給・帰還・入荷・整理・任意の日送りと保存を検証します。報酬・成長・冒険の詳細は未実装です。
