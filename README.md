# Guild Keeper

React + TypeScript + Vite による倉庫管理ゲームです。160枠・48個（8品目各6個）の初期在庫から好きな品を勇者の持ち物へ準備し、冒険中に整理して、帰還・入荷・翌日を繰り返す基本ループ試遊版です。PC・スマートフォンに対応しています。

Guild Keeper（作品の仮称「勇者の倉庫番」）は、「勇者にはならない。勇者を倉庫から支える。」を軸に、RPG 世界の倉庫番として大量の装備や消耗品を探し、整理し、アップグレードや自動化で作業を効率化していくブラウザゲームです。倉庫作業とその改善を中心とし、ギルド経営や戦闘を主目的にはしません。

自由支給（F-032）、1日1回の自動出発（F-033）、時間経過する冒険（F-034）を実装しています。帰還・入荷（F-008）、任意の日送り（F-009）、自動保存（F-010）を再利用し、旧セーブを移行します。F-035 の操作欄・ドラッグを改善しましたが、人による発見性評価は残しています。正式完了は各実装PRのmainマージ時です。

サンドボックス向けの暫定時間を使っていますが、スキル・設備等を自由に切り替える試用環境（F-036）やストーリーモードは未実装です。

ユーザーが次に追加したいゲーム機能を選び、Codex が依存関係と内部タスクを整理して実装します。「今、何が作れる？」と尋ねると、最新の `main` と進行中の PR に基づく候補を提示します。フェーズは厳密な着手順ではなく、個々の機能の依存関係で判断します。明示的に選択されるまで候補の実装は開始しません。

## 試遊版の遊び方

1. 初回の短い操作案内を閉じ、冒険予定を確認します。案内は一度閉じると自動再表示せず、ヘッダーの「?」で再確認できます。
2. 倉庫・勇者のセルはアイコンのみ。PCはドラッグ、スマホは長押しで移動し、倉庫内は品に重ねると交換します。ダブルクリック／ダブルタップで勇者へ支給・倉庫へ返却できます。倉庫・勇者間は空きがなければ理由を表示します。
3. 1回押すと詳細を確認できます。詳細の「操作」から支給・返却や、移動先を指定する操作も可能で、ドラッグ・ダブル操作は必須ではありません。
4. 「出発」でその日1回の冒険へ。短いセリフと所要時間を表示し、自動で閉じます。持ち物は帰還まで変更できず、倉庫は自由に整理できます。60〜180秒の所要時間と残り時間は、再読込・ブラウザ終了をまたいでも保持します。
5. 「帰還を迎える」で専用リザルトを開き、返却装備・戦利品・使用した消耗品を確認します。空きと選択数を見ながら「選択品を入庫」。満杯なら閉じて整理し、「リザルト」から再選別できます。選択と結果は再読込でも復元され、再表示による再生成はありません。
6. 未選択品は勇者に保持し、8枠超過品は一時選別へ保存。次の冒険には8枠だけを持参します。帰還後の「翌日へ」まで日付は進まず、配置・在庫・持ち越し・冒険記録を保持します。

新規ゲームは160枠の先頭48枠へ8品目各6個を混在配置し、後ろ112枠を空けます。既存セーブの配置・個体・数量は変更しません。

状態はこのブラウザのlocalStorageにversion 4で自動保存します。version 1〜3の移行、旧受取待ちの一時選別への保持、破損・非対応時の上書き停止を維持します。保存失敗は警告し、前回の保存を保護します。左メニューは保存状態と確認付き初期化のみ。端末間同期・複数タブ同時編集は対象外です。端末の時計を変えると残り時間も変わります。詳細は [ゲーム仕様書](docs/GAME_DESIGN.md#compact-playtest-ui) を参照してください。

## 開発

Node.js 24.x と npm を使用します（`.nvmrc` 参照）。外部サービスや環境変数は不要です。

```sh
npm ci
npm run dev
```

開発サーバーの `/guild-keeper/` を開いてください。

```sh
npm run lint     # Oxlint による静的解析
npm run build    # TypeScript の型チェックと本番ビルド
npm run preview  # dist のローカル確認
npm test         # Node.js 標準ランナーによるロジックテスト
```

ビルド成果物は `dist/` に生成されます。ブラウザでの受け入れテストは Playwright を使います。

```sh
npx playwright install chromium
npm run test:e2e
```

テストは本番ビルドを作成し、ポート 4175 のプレビューを自動起動します。PC とスマホの Chromium でタップ・クリック、自由支給・ドラッグ／長押し・タップ・通常スクロールと端スクロール、複数日の冒険時間と再開、配置の引き継ぎ、旧セーブ移行、破損保護、保存失敗、初期化、小画面レイアウトを検証します。既存 Chromium を利用するクラウド環境では次のコマンドで実行できます。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

ロジックテストは CI でも実行します。E2E は上記コマンドで実行し、実機 Safari / iOS での確認は別途必要です。

## 構成

- `src/App.tsx`: 倉庫・注文・操作 UI
- `src/game/data.ts`: 初期在庫・品目データ・旧形式移行用の注文定義
- `src/game/game.ts`: UI に依存しないゲーム状態と操作判定
- `src/game/save.ts`, `legacy.ts`: version 4の保存・検証と旧形式の検証・移行
- `src/ui/useItemDrag.ts`: 標準ドラッグ・長押し・追従表示・端スクロール
- `src/ui/Modal.tsx`, `ReturnResults.tsx`, `preferences.ts`: 冒険詳細・リザルトのモーダル、選別表示、初回案内の記録
- `src/game/arrivals.ts`: 再現可能な帰還抽選と、空き枠への入庫・受取待ち処理
- `tests/`: ロジックとブラウザの受け入れテスト
- `src/App.css`, `src/index.css`: レスポンシブレイアウトと共通スタイル
- `vite.config.ts`: GitHub Pages のベースパス `/guild-keeper/`
- `.github/workflows/deploy.yml`: Lint・ビルド・Pages デプロイ

## GitHub Pages

1. GitHub リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. 初回コミットを `main` に push します。
3. Actions の「Deploy to GitHub Pages」が成功すると https://70nanon.github.io/guild-keeper/ に公開されます。

`main` への push で自動デプロイします。Pull Request は Lint とビルドのみ実行します。Actions タブの `workflow_dispatch` からも `main` を選択して実行できます。Pages の利用可否や権限はリポジトリ設定に依存します。

アセットは import または `import.meta.env.BASE_URL` を使用し、サイトルートを前提としたパスを避けてください。ルーターは未導入です。将来導入する場合は Pages の直接アクセス時の挙動も検討してください。
